# Публикуй посты одним Markdown-файлом

Это последний шаг. После настройки сайта автору больше не нужно знать Jekyll front matter, Liquid или структуру \`_posts/\`.

## Самый простой способ

Создай обычный Markdown-файл в папке \`posts/\`.

Например:

\`Как я решил проблему.md\`

Внутри оставь только содержание:

    Я начал с проблемы...

    ## Что оказалось причиной

    Оказалось, что...

    ## Решение

    Нужно было...

Никаких \`---\`, \`layout:\`, \`title:\`, \`date:\` и имён вида \`YYYY-MM-DD-title.md\`.

## Как попросить ChatGPT

Если GitHub подключён и ChatGPT имеет право менять репозиторий:

> Добавь следующий пост в папку \`posts/\` как обычный Markdown-файл без front matter, затем проверь сборку, публикацию и опубликованную страницу:
>
> [вставь текст поста]

Или попроси создать файл с заданным названием и содержимым.

Вся служебная работа остаётся на стороне сборки:

**имя файла → title → первый Git commit → date → Jekyll post → GitHub Pages.**

Конечная модель проста: автор работает с обычными Markdown-файлами, а публикационная система сама добавляет необходимые Jekyll-метаданные.
