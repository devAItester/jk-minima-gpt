# Сделай папку для постов без front matter

Теперь вводится главное упрощение для автора блога: исходный Markdown не должен содержать служебный YAML-блок Jekyll.

## Запрос

> Добавь в репозиторий отдельную папку \`posts/\` для моих исходных Markdown-постов.
>
> Файлы в этой папке должны быть обычным Markdown без front matter.
>
> Содержимое \`posts/\` не должно публиковаться как исходные файлы.
>
> Перед сборкой преобразуй эти файлы во временные Jekyll posts.
>
> Не заставляй автора писать \`---\`, \`layout\`, \`title\` или \`date\`.

Обычная папка с Markdown без front matter не является Jekyll-постом. Поэтому служебный слой должен существовать между исходным материалом и Jekyll.
